## 0. 统一前置：所有模板共用的搭建底座

### 0.1 本地环境启动

1. 安装依赖

```sh
pnpm install
```

2. 启动开发环境

```sh
pnpm dev
```

3. 验证服务

```sh
curl http://localhost:3100/api/health
curl http://localhost:3100/api/companies
```

### 0.2 常见启动故障快速处理

当前仓库实测常见失败：
- embedded PostgreSQL 报错：pre-existing shared memory block is still in use
- tsx not found

处理顺序：

1. 结束残留进程（Windows PowerShell）

```powershell
Get-Process | Where-Object { $_.ProcessName -match 'postgres|node|tsx|paperclip' } | Stop-Process -Force
```

2. 重新安装依赖（确保 tsx 可用）

```sh
pnpm install
```

3. 如仍异常，清理本地嵌入式数据库并重启

```sh
rm -rf data/pglite
pnpm dev
```

### 0.3 统一设计原则

1. 每个业务边界都落到 Company，严格隔离上下文与预算。
2. 每个 Goal 只承载一个清晰结果，避免大而全。
3. 每个 Issue 只有一个负责人 Agent，保持原子签出。
4. 对外动作必须经过 Approval Gate（发客户、发生产、删数据）。
5. 核心 KPI 不是总收入，而是每工时收益。

## 1. 模板 A：一人 SaaS 产品公司（最通用）

### 1.1 适用场景

- 你是独立开发者，目标 3-6 个月做到首批稳定 MRR。
- 你想把开发、运营、内容分给不同 Agent 并行执行。

### 1.2 目标架构

```text
Company: SaaS-核心产品
  Goal-1: 产品开发（Sprint）
    Issue: 需求拆解 / 后端 / 前端 / 测试 / 发布
  Goal-2: 用户增长
    Issue: 内容生产 / Landing 页优化 / 渠道实验
  Goal-3: 用户支持
    Issue: 工单归类 / 回复草稿 / FAQ 更新
```

### 1.3 分步搭建（Day 1-7）

1. 创建 Company：产品主线。
2. 配置 3 个 Agent：工程、增长、支持。
3. 创建 Goal：开发、增长、支持三条主线。
4. 为 Goal 建 Issue 模板：每类任务固定输入和产出格式。
5. 打开审批门：生产发布、价格改动、用户通知默认需审批。
6. 设预算：先低后高，初期建议每月 $80-$150。

### 1.4 Agent 建议

- 工程 Agent：claude_local 或 codex_local，负责实现与重构。
- 增长 Agent：claude_local，负责内容提纲、投放文案、AB 测试方案。
- 支持 Agent：process/http 结合，负责知识库检索和工单草拟。

### 1.5 关键 KPI

- 周交付功能数
- 周活跃用户增长
- 用户反馈闭环时间
- 每工时收益（必须持续上升）

### 1.6 何时升级

- 当 Agent 自动完成率连续 4 周 > 70%，新增 Goal：渠道合作或生态集成。

## 2. 模板 B：AI 内容工厂（Newsletter/SEO/短内容）

### 2.1 适用场景

- 你希望用内容驱动获客并沉淀长期复利流量。
- 你想把选题、研究、写作、分发变成可复用流水线。

### 2.2 目标架构

```text
Company: Content-Factory
  Goal-1: 每周主题内容
    Issue: 选题 -> 研究 -> 初稿 -> 编辑 -> 发布
  Goal-2: 分发增长
    Issue: 多平台改写 -> 发布排期 -> 复盘
  Goal-3: 商业化
    Issue: 赞助位拓展 / 联盟分销 / 付费内容实验
```

### 2.3 分步搭建（Week 1-2）

1. 建立内容知识库 Goal：品牌语气、禁用词、目标受众。
2. 设计单篇内容标准 Issue 模板：
   - 输入：关键词、受众、主张
   - 输出：标题 3 版、正文、CTA、分发短文
3. 设置质量审批：公开发布前必须人工过稿。
4. 配置预算：研究模型用低成本，成稿模型用高质量。

### 2.4 已验证实践映射

- Meerkats 经验：越早做内容越好，内容本身是获客系统。
- Anthropic 经验：不要复杂代理树，先用清晰串行流程。

### 2.5 关键 KPI

- 每周发布频次（稳定性）
- 内容到线索转化率
- 自然流量增长率
- 内容生产每工时收益

### 2.6 何时升级

- 内容月复购变现稳定后，新增 Goal：课程/模板/工具产品化。

## 3. 模板 C：AI 增强服务公司（咨询/代运营/设计/开发外包）

### 3.1 适用场景

- 你已有服务能力，想在不扩招的情况下提升交付规模。
- 你希望从项目制转月费制，提升现金流稳定性。

### 3.2 目标架构

```text
Company: Client-XXX
  Goal-1: 客户知识库维护（持续）
  Goal-2: 月度交付
  Goal-3: 增长建议与复盘
```

每个客户一个 Company，不混上下文，不混预算。

### 3.3 分步搭建（首个客户）

1. 建 Company：客户名 + 服务线。
2. 建 Goal-知识库：记录客户偏好、历史决策、禁忌事项。
3. 建 Goal-交付：按周拆解 Issue。
4. 建 Goal-复盘：每周自动汇总已完成/风险/下周计划。
5. 启用审批门：对客输出默认需人工审核。
6. 设置预算和告警阈值：80% 告警，超限自动暂停。

### 3.4 已验证实践映射

- Garcy Studio 经验：客户简报自动化是单点高杠杆。
- AI 成本通常低于人工时间成本，重点优化人工介入比例。
- 月费制比项目制更容易形成稳定经营飞轮。

### 3.5 关键 KPI

- 客户续约率
- 客户毛利率
- 交付准时率
- 每客户每工时收益

### 3.6 何时升级

- 3 个以上月费客户稳定续约后，抽象内部工具，进入产品化路线。

## 4. 模板 D：成果即服务（Outcome-as-a-Service）

### 4.1 适用场景

- 客户只关心结果，不关心过程和工具。
- 你希望按产出收费而不是按人天收费。

### 4.2 目标架构

```text
Company: Outcome-Production
  Goal-1: 标准产出流水线
    Issue: 输入校验 -> 执行 -> 质检 -> 交付
  Goal-2: 成本与利润控制
    Issue: 每批次成本核算 / 报价优化
  Goal-3: 交付质量治理
    Issue: 返工原因归档 / 模板迭代
```

### 4.3 分步搭建（2 周可上线）

1. 定义一个可验证结果：如 100 条合格线索、10 篇 SEO 文。
2. 做一条最小产线：先串行，后并行。
3. 固化质检 Issue：输出不达标自动回退重试。
4. 固化成本追踪：每批次记录 tokens、时间、返工次数。
5. 建立报价公式并每周修正。

### 4.4 定价建议

- 先按“客户替代成本”的 60%-80% 定价。
- 用固定包（可预测）替代纯消费计费（易焦虑）。

### 4.5 关键 KPI

- 单批次毛利率
- 一次通过率
- 客户可感知结果达成率
- 交付周期（越短越有溢价）

### 4.6 何时升级

- 当同类任务重复率高、返工低，优先做模板产品或轻量 SaaS。

## 5. 模板 E：多产品一人控股（Portfolio 公司）

### 5.1 适用场景

- 你同时运行多个小产品/服务，想统一控制风险与资源。
- 你需要在增长与维护之间做动态资源分配。

### 5.2 目标架构

```text
Company: Portfolio-HoldCo
  Goal-1: 产品 A 增长
  Goal-2: 产品 B 维护
  Goal-3: 新机会孵化
  Goal-4: 资金与预算治理
```

### 5.3 分步搭建

1. 按业务线拆 Company 或子域 Goal，不让上下文互相污染。
2. 建统一周会 Issue：自动汇总每线 KPI、风险、下周建议。
3. 用预算硬上限防止某条线吞噬全部资源。
4. 每月做一次资源再分配：砍掉低效线，追加高效线。

### 5.4 决策规则（建议硬编码到 Issue 模板）

- 连续 4 周低增长且低毛利：降级维护或关停。
- 连续 4 周高增长且高毛利：加预算、加自动化。

### 5.5 关键 KPI

- 组合总利润率
- 资金跑道（月）
- 机会成本（人时分配）
- 单业务线每工时收益

## 6. 30 天落地路线图（可直接执行）

### 第 1 周：搭底座

1. 启动环境并完成健康检查。
2. 选定一个模板（A-E）作为主线。
3. 创建 1 个 Company + 3 个 Goal + 10 个初始 Issue。
4. 配置 2-3 个 Agent 与审批门。

### 第 2 周：跑第一条流水线

1. 只跑一个“楔子任务”，不要扩线。
2. 每个 Issue 执行后做一次复盘评论。
3. 把高频手工动作写进模板或系统提示词。

### 第 3 周：稳定质量

1. 引入质检 Issue（自动+人工）。
2. 建预算告警和自动暂停策略。
3. 固化周报 Issue（自动生成经营看板）。

### 第 4 周：验证商业结果

1. 评估每工时收益变化。
2. 评估续约/复购/留存信号。
3. 决定：扩线、提价、或收敛聚焦。

## 7. 模板选择器（你该从哪套开始）

- 你会开发且想做产品：从模板 A 开始。
- 你擅长内容与分发：从模板 B 开始。
- 你已有客户和交付能力：从模板 C 开始。
- 你要按结果收费做高毛利：从模板 D 开始。
- 你已有多条业务线：从模板 E 开始。

不确定时，默认从模板 C（服务）起步，再走服务 -> 工具 -> SaaS。

---

## 8. 交付质量与治理红线

1. 对外发布内容必须审批。
2. 任何生产环境改动必须审批。
3. 涉及用户数据与支付的代码必须人工复审。
4. 超预算自动暂停，不允许例外放行。
5. 任务跑偏时先暂停再修复，不要带病继续。

## 10. 一句话总结

Paperclip 最有效的用法不是“多上几个 Agent”，而是“先用一个高价值楔子任务跑通收益飞轮，再用 Company/Goal/Issue 把它系统化、标准化、可复制化”。
